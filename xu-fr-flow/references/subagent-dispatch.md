# 子 Agent 分派与交接

## 能力驱动分派模型（Harness 无关）

本技能组不绑定任何单一 Harness。规则只依赖宿主实际能力和可核验证据，
在任意支持独立子 Agent 上下文的 Harness 中按同一套契约执行。

先核对能否创建独立子 Agent、取得实际结果、配置权限和续接上下文。
有合规角色配置则优先使用；没有时，用通用工具新建独立上下文并指定逻辑角色。
已被拒绝的权限须由有权者处理，不能换工具绕过。

用宿主可核对的上下文身份校验隔离，不依赖模型或工具不同来推断隔离。
在 `flow-ledger` 记录稳定 `contextId`、所属范围 `contextScope`、
`runHandle`（跟踪运行）与 `resumeHandle`（续接会话）。
原上下文续接可更新句柄并保持 `contextId`；新同角色上下文才登记新身份和 `handoffs[]`。
只有任务 ID 时须取得可追溯到独立上下文创建的工具证据。
外部人工角色记 `actorType: "external-human"` 与可核对身份，不虚构 Agent 会话。

## Reviewer 两级只读隔离协议

所有只读角色（`fr-requirements`、`fr-design-reviewer`、`fr-code-reviewer`、`fr-test-case-reviewer`）执行以下两级只读隔离：

1. **一级（`enforced`，默认必需）**：使用宿主禁写工具、只读沙箱或隔离只读副本限制写入。
   仅分开目录或在提示词中写“不要写入”不构成强只读。
2. **二级（`verified-zero-write`，仅显式批准后降级）**：无法强制禁写时按以下步骤处理：
   - 先停止正式评审并报告能力缺口，不得用口头只读约束直接放行。
   - 用户获知缺口并明确批准后，主 Agent 才可继续派工。
   - 派工前后分别采集可核验的工作区／VCS 指纹，确认 `beforeFingerprint === afterFingerprint`。
   - 在台账和结论中标注 `verified-zero-write`、`approvalRef` 与前后指纹。
   - 检出非预期写入或指纹漂移时，立即作废评审结论并进入 `BLOCKED`。

## 分派和验收

- **完整分派**：首次调用即给出逻辑角色、目标、范围、固定输入及版本、权限、交付物、通过条件和阻塞反馈要求。
  明确禁止角色子 Agent 再次委派；宿主支持时关闭其分派权限。
- **直接履约**：子 Agent 返回状态、实际产物或位置、对应版本、检查范围、可核对证据与未决项。
  需要额外分派时说明原因，由主 Agent 决定；验收只认可角色直接完成的工作。
- **验收流转**：主 Agent 核对隔离、版本、权限、只读证据和完整性后推进，并同步台账。
  启动回执不是产物；先取得上游实际交付，再分派有依赖的下游角色。
- **原角色返工**：优先用最新续接句柄续接原上下文，保留上轮结论、逐项问题与有效轮次。
  无法续接时，向同角色新独立上下文交接原因、版本、反馈、增量、证据、轮次与未结项。
  接手 Reviewer 至少复核未结项和增量，不能凭交接直接通过。
- **能力或证据缺口**：缺独立上下文、只读权限（且未获降级批准）或交接证据时报告阻塞。
  可交付已有产物与可核验外部人工证据，人工确认只能由用户给出。

## 状态卡与按需台账

日常阶段切换和门禁等待只输出紧凑状态卡；需要跨会话交接、调用台账校验或用户明确要求时，
才按 [基线与文档元数据](requirements-and-stages.md) 输出稀疏 `flow-ledger` JSON。
