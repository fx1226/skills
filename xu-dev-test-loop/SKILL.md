# xu-dev-test-loop

主 Agent 只编排、核对入口／版本／人工确认、转交材料和整合实际输出，不亲自写正式用例、评审用例、执行正式测试或修代码，也不补写角色结论。用例作者 Agent、用例 Reviewer Agent、测试执行 Agent 须为三个不同的独立上下文，且各自独立于主 Agent、入口记录的开发 Agent 和代码 Reviewer Agent；同一 Agent 不得跨角色顺序切换，包括原开发改任测试执行者或原代码 Reviewer 改任用例 Reviewer。作者负责设计、覆盖自查、答复和修改，不执行正式用例；Reviewer 只读评审，不修改用例或执行；执行者执行已批准用例、记录证据和形成执行／QA 交接材料，不设计或修改用例、改预期或修代码。

**OpenCode 分派：** 用 `subagent` 工具的 `agent` 参数精确指定用例作者 `fr-test-case-author`、用例 Reviewer `fr-test-case-reviewer`、测试执行者 `fr-test-executor`，分别保存其 `sessionID`；作者返工、Reviewer 复审及执行／复测续接各自原会话。缺陷修复和代码增量复审分别续接入口原 `fr-developer`、`fr-code-reviewer` 会话；不可续接时按同身份交接台账给对应专用 Agent 的接替会话。原 `fr-test-executor` 会话复测，不可续接时同身份交接。专用 Agent ID 缺失或调用权限受阻时停止对应环节并报告；不得用 `tester` 同时承担作者和执行、用通用 `review` 替代专用 Reviewer，或由主 Agent 兜底。会话 ID 不可得或不可续接时，不得冒充原会话；先核实并按同身份交接规则处理。

每个角色的首次调用必须一次性包含完整角色任务、当前已有材料、交付要求和授权，不得先创建或预占 `sessionID` 再补任务，也不得以占位、等待、保活或无操作作为任务内容。启动回执不等于实际结果。先取得作者实际用例及覆盖自查，再分派 Reviewer；取得 Reviewer 对当前用例版本的实际通过结论后交用户确认，取得明确确认后才分派执行者。已有符合门禁的实际产物可核实后沿用，不为补齐顺序重复分派。

返工尽量沿用原作者和原 Reviewer，执行及复测尽量沿用原执行者；角色不可用时只能交接给同身份的独立 Agent，移交版本、轮次、结论、证据及未结项等台账，不能跨角色复用或由主 Agent 兜底。缺少所需独立角色时停止对应环节并报告缺口。所有结论绑定具体版本，用户的确认不等于授权提交、推送、部署或设备改状态。

1. **核对入口。** 固定明确的代码快照，核实该快照已有研发自测、diff 自查、独立代码审查通过且无未解决的代码审查阻塞项。任一条件缺失时停止正式用例设计及用例评审，说明缺口，进入或建议使用 `xu-dev-review-loop`；可指出资料或环境缺口。核对入口记录及本任务各角色的身份、Agent 会话和交接台账，分派或同身份接替前确认无跨角色碰撞；可核对的外部人工审查记录外部身份和依据，不虚构 Agent 会话。台账显示身份碰撞时禁止分派；信息不足以证明隔离时先询问或报告受阻，不能声称满足严格隔离。**完成条件：** 四项入口证据均对应当前快照，拟分派角色的隔离可由身份和交接证据核实。
2. **设计并自查用例。** 派用例作者 Agent 读取 [用例设计与评审](references/case-design-and-review.md)，按需求与约定设计 Markdown 用例，逐条核对验收条件的覆盖或不适用依据。**完成条件：** 作者的用例版本、需求依据及覆盖自查可供独立评审；依据不足的行为保持待确认。
3. **独立评审并闭环。** 将作者材料交另一独立上下文的只读用例 Reviewer；退回后交作者答复、修改，再交原 Reviewer 增量复审，遵守同一参考的轮次和停止条件。**完成条件：** 独立 Reviewer 对当前用例版本明确通过且无未解阻塞；无独立能力时仅转交已有草案及自查，不宣称通过。
4. **人工确认。** 将评审结论及当前用例版本交用户，取得用户明确人工确认后才正式执行；Agent 评审不代表研发经理或测试经理批准。**完成条件：** 有可关联当前用例版本的明确确认。
5. **执行、缺陷流转与交接。** 确认后派第三个独立上下文的测试执行 Agent 读取 [执行与交接](references/execution-and-handoff.md)，按实际环境和授权执行、记录证据并形成交接材料；主 Agent 按参考流转缺陷和整合实际输出。已有用例评审通过并人工确认后独立调用本技能，也须核对入口及版本并派独立执行者；恢复执行记录还须核对执行者身份、交接和版本。**完成条件：** 当前版本必测项全部通过且无未解阻塞，才能报告研发测试完成可交 QA；否则报告实际状态，由用户决定是否带风险交接。研发交付不等于 QA 通过。

文档默认在对话中输出 Markdown；仅当用户给出保存路径并明确授权写入时才落盘，给出路径本身不等于写入授权。提交、推送、部署及设备改状态须分别获得授权。
