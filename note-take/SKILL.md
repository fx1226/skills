# note-take · 对话记录

将对话中值得长期保留的增量提炼为规则，而不是把对话存档。每条常驻规则都应值得在其作用域内的未来任务中反复出现；没有增量时，零写入就是完成。

## 1. 筛选候选

从当前对话的用户要求、纠正和已确认决定中提取候选。每条都须满足：

- **有来源**：能指出用户的明确表述或确认；Agent 的推测、外部材料和工具输出本身不构成用户约定。
- **长期有效**：超出当前任务仍成立，且不依赖容易变化的运行状态。
- **改变行动**：能说清它将在什么情况下改变未来 Agent 的哪项选择或行为。
- **值得常驻**：不是默认常识，也不是从配置、代码或现有权威文档中一次直接查找就能得到的事实。

进度、完成记录、临时错误、一次性要求留在本次会话。复杂操作流程留给专项文档或 Skill；规则只在确有必要时提供带触发条件的指针。凭据与敏感个人或客户信息不得进入规则文件。

完成条件：每个保留候选都有来源、未来用途和拟定作用域；其余舍弃。信息不足但可能重要的内容只作为待确认候选。

## 2. 确定建议作用域

- **全局**：用户明确表达跨项目适用的偏好或工作边界，目标为当前 Agent 的全局规则入口。
- **项目**：依赖特定代码库、团队或业务背景的约定，目标为该项目根目录的规则入口。确认实际项目根目录，不能将当前工作目录直接当作根目录。
- 范围不明时先给候选及建议范围，仅询问会改变落点的问题；从单项目经验推导出的普遍建议仍是建议。

“评估／草稿／只读”仅输出建议，止于提案，不进入写入流程。涉及操作权限或安全边界时，保留用户明确表达的准确范围。

完成条件：每条候选都有建议作用域，或已明确标出需要用户决定的范围问题。

## 3. 找到实际生效的入口

以当前 Agent 的已加载上下文、配置、已安装版本文档或加载实现为证据，核实：

1. 全局目录或项目根目录，以及支持的规则文件名。优先沿用现有有效入口；新建时，在确认支持的名称中优先 `AGENTS.md`，其次 `RULES.md`。
2. 同目录的覆盖文件、文件优先级和路径重定向，确认拟编辑文件确实会被加载。文件存在并不等于生效。
3. 适用的全局、祖先目录及项目规则中，是否已有等价要求、不同范围的例外或与候选冲突的要求。

按实际支持情况选择入口，不能把其他 Agent 的路径或加载约定照搬过来。若仅支持其他名称，或用户指定的文件不能生效，说明原因并确认替代目标。无法核实入口时交付草稿，不靠创建多个候选文件碰运气。

完成条件：目标路径、加载依据和既有相关规则均已明确。

## 4. 拟定最小增量

先读完整目标文件，再拟定处理方式，此时保持文件不变：

| 当前状态 | 操作 |
| --- | --- |
| 已有等价规则 | 保持不变 |
| 同一规则缺少必要条件 | 在原处补全条件 |
| 用户明确纠正了旧规则 | 在原处更新或移除被撤销部分 |
| 与现有规则冲突且没有明确取舍 | 展示冲突并询问，暂停该条写入 |
| 确为新增 | 放到最相关章节；无合适章节时再加简短标题 |
| 权威内容已在专项文档 | 必要时仅补“何时读取＋文档路径”的指针 |

写成可执行的“适用条件＋行动”，必要时保留防止误用的理由。保持原有语言和结构，每个含义只有一个权威位置；项目例外须明确范围。新建规则文件使用简短标题与必要条目即可。

常驻文件承载当前约定，来源解释与本次修改说明留在回复中；无需追加时间戳、对话摘录或变更流水账。

完成条件：形成可供用户审阅的最小改动，没有重复、无关重排或意外扩大范围。已有等价规则时无需提问或写入。

## 5. 询问确认后写入

无论全局还是项目，每次有实际改动都先向用户展示：

- **位置与作用域**：具体文件路径，以及全局或哪个项目。
- **拟记录内容**：将要写入的准确文本。
- **修改方式**：新增、修改或删除；替换旧内容时展示前后差异，新建文件时明确说明。

随后询问：“是否按上述内容记录到这个位置？”有结构化提问工具时优先使用，提供确认、调整和不记录的选择；否则用普通消息询问并等待回复。多条候选可一次列出，明确用户确认了哪些条目，部分同意仅写入对应部分。

“记住这件事”、历史授权或用户确认事实正确，都不能替代对本次具体内容和落点的许可。只有用户明确批准上述提案后才落盘；不回复、取消或拒绝均保持文件不变，也不转存到其他位置。调整内容、路径或修改方式后，展示更新后的提案并重新确认；同一提案已经获准则直接执行，无需重复询问。

写入前重新检查目标是否变化；若变化影响已确认的提案，先更新提案并重新确认。只应用获准增量，保留用户已有内容与未提交改动。

完成条件：仅有明确确认的改动被写入；其他候选保持未写入状态。

## 6. 验证并交付

读回目标文件并检查差异，确认规则与获准提案一致、落点正确、引用存在，且原有无关内容保留。发现偏差时按第 5 步处理需要调整的提案。

简短报告实际路径及新增、更新或保持不变的规则。区分“已写入”与“已加载”：只有确认当前上下文已加载新内容才能宣称生效，否则说明当前 Agent 所需的重载或新会话步骤。无合格增量时直接说明，不为完成任务凑条目。

本技能只处理获授权的规则文件，不自行安装技能、调整记忆插件、迁移历史记录或同步写入其他存储；另有上位要求时遵循并说明边界。
