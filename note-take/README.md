# note-take（对话记录）草稿

把对话中能改变未来行动的长期约定，写到当前 Agent 真正加载的规则入口。它不是通用记忆库：项目事实继续以代码、配置和权威文档为准，复杂流程交给专项文档或 Skill。

## 设计取舍

- 自动识别候选，每次先展示准确内容、具体路径和修改方式，询问是否记录；用户明确确认本次提案后才写入。历史授权不替代这次确认，取消或拒绝不写入；“先评估／给草稿”止于建议。
- 全局与项目分别归位，已有约定原处更新；没有合格增量就不写。
- `AGENTS.md` / `RULES.md` 的支持与优先级由运行它的 Agent 决定，不内置跨产品路径猜测。
- 只增加这项可选工作流，不替换现有记忆机制，也不自动安装或修改全局规则。

## 运行时兼容性

执行时按 [SKILL.md 第 3 步](SKILL.md#3-找到实际生效的入口)核实规则入口与加载方式。使用 Pi 时，查阅已安装版本随附的官方 `docs/configuration.md`；安装或加载技能时查阅 `docs/skills.md`。本技能不维护各版本的路径和文件名清单。

## 行为验收（待执行）

`test-prompts.json` 提供 16 个场景，包含独立的作用域不明场景，覆盖筛选、归位、去重、确认和拒绝等边界。每个场景的 `expected` 是应观察到的行为，`hard_failures` 是一票否决条件；任一失败条件命中即判失败，即使部分预期已满足。

在临时目录及隔离 Agent 配置下准备场景文件，先不加载技能运行基线，再加载技能运行相同场景。检查实际文件差异、工具调用轨迹与回复，确认写入发生在许可之后；仅在回复中声称会等待确认不算通过。每轮重置测试目录，避免上一轮的写入污染结果；禁止使用真实凭据或实际全局规则文件作为测试素材。

当前仅完成草稿内容审阅、JSON 与文件结构检查，尚未做上述真实 Agent 的前后对照。通过行为验收后，再决定是否安装；安装本身不改变逐次确认后写入的要求。
