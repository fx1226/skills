# xu-review-loop

把「改动 → 构建 → 功能测试 → 送审 → 审查」做成有硬门禁、有轮次上限的闭环。开发和审查是两个独立子 Agent；门禁判定、轮次计数、停止报告由 `workflow.js` 执行，不靠模型自觉。

## 工作契约

- **派发，不代劳**：固定参数、发起闭环、处理结果。改代码、跑测试、下审查结论都交给子 Agent；你动手会让「独立审查」失效。
- **approved 只是「可提交」**：提交是单独动作，按本会话已有的授权执行；没有授权就回报可提交，不替用户拍板。
- **stopped 是正常出口**：到达轮次上限仍不通过时，把原因和残留问题交给用户，不写成「基本通过」，也不提交。
- **区分流程故障与代码结论**：`dev-failed` / `review-failed` 表示子 Agent 没跑完，不是审查结论；说明断在哪一环，再决定是否重跑。

## 1. 固定参数

| 参数 | 取值 |
|---|---|
| `goal` | 这次要达成什么：新增功能还是修 Bug，验收标准是什么 |
| `base` | 审查基线。未提交改动用 `HEAD`；分支改动用分叉点或目标分支 |
| `build` | 构建命令，在仓库根目录可执行 |
| `test` | 功能测试命令 |
| `maxRounds` | 送审轮次上限，默认 10 |
| `notes` | 额外约束：不能碰的文件、必须保留的行为、环境限制 |

闭环在**当前会话工作目录**里跑：目标仓库不是当前目录时，先用工作目录工具（如 `working_directory`）切到仓库根，跑完再切回。开跑前确认 `git diff <base>` 能反映被审改动；构建或测试命令不确定时向用户要，不要猜。

**完成条件**：六项齐备；`base` 下的 diff 能重现本次改动，而不是空 diff 或混入无关改动。

## 2. 发起闭环

读技能目录下的 `workflow.js`，把内容原样作为 `script` 传给 `workflow` 工具：

```js
workflow({
  meta: {
    name: "xu-review-loop",
    description: `${goal} · 闭环最多 ${maxRounds} 轮`,
    phases: [{ title: "开发自测" }, { title: "审查" }]
  },
  args: { goal, base, build, test, maxRounds, notes },
  script: /* workflow.js 的内容 */,
  run_in_background: true // 预计超过几分钟就后台跑
});
```

`script` 用 `workflow.js` 原文，不改参数名、不删钩子；`args` 缺 `goal`/`build`/`test` 时脚本直接返回 `bad-args`。

**完成条件**：拿到结果对象。后台运行以 `job_output` 的完成为准，启动成功不算跑完。

## 3. 处理结果

| status | 含义 | 你要做的 |
|---|---|---|
| `approved` | 测试与审查都通过 | 汇报改了什么、怎么验的、审查摘要与遗留的非阻塞项；按授权提交 |
| `stopped` | 第 N 轮送审仍不通过 | 报告轮次、原因、`residual` 中的阻塞项与测试缺口；不提交 |
| `blocked` | 开发 Agent 自测卡死 | 报告 `reason` 与已尝试的做法，决定换思路还是找用户 |
| `dev-failed` / `review-failed` | 子 Agent 没跑完 | 说明断在第几轮、哪一环；这是流程故障，不是审查结论 |
| `bad-args` | 参数不全 | 补齐参数重新发起 |

`dev-failed` / `review-failed` 后的重跑是另一次运行、轮次从 1 起算，不要用重跑绕过轮次上限。

**完成条件**：状态、轮次与证据对得上；`stopped` 的残留问题逐条列出，阻塞项没有被说成建议。

## 4. 交付

- 通过：一句话结论 + 验证依据（构建、测试命令与结果）+ 审查摘要 + 未处理项。
- 停止：第几轮停的、为什么、还残留什么、下一步建议（换方案 / 拆小改动 / 人工接手）。

提交只在用户已授权时执行，并在交付里写明 commit 与提交范围；未经授权的「可提交」不等于已提交。

## 边界

- 轮次只数送审；自测循环在开发 Agent 单次调用内收敛，连续失败由它返回 `blocked`。
- 审查 Agent 的「只读」靠提示词约束；要硬约束得在工具层做 guard。
- 当前 preset 没有 `workflow` 工具时本技能无法执行；主 Agent 手动跑一遍不算数——那样没有独立审查，也没有可靠轮次计数。
