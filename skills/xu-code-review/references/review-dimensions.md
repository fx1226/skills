# 通用审查维度与路由

本文件适用于每次审查。先按路径和行为筛选，再对适用风险深入；不要求每个文件执行所有专项。排除某个高影响风险时给出事实依据，不以“通常不会发生”代替。

## 16 个维度

| 维度 | 必须回答的问题 | 深入条件与参考 |
|---|---|---|
| 1. 需求与业务正确性 | 明确需求是否逐项实现？输入输出、状态和权限是否符合业务不变量？ | 有规格即逐项映射到实现与验证；未知要求标缺口 |
| 2. 设计与职责 | 职责、依赖方向、接口是否合适？已有能力能否复用？复杂度是否服务当前目标？ | 接口、职责或抽象变化 → design-smells |
| 3. 初始化与生命周期 | 每条使用路径是否取得有效状态？部分初始化、重置、销毁是否闭合？ | 构造、注册回调、启动停止、重连或对象复用 → R1 |
| 4. 输入与边界 | 空、零、极值、非法值及组合边界是否符合契约？信任边界在哪里？ | 新输入、解析、索引、长度、分页、时间比较 → R2；不可信输入同时看 R7 |
| 5. 数值与类型 | 运算及转换是否符合语言语义？单位、范围、精度及舍入是否一致？ | 算术、计数、容量、金额、时间或序列化变化 → R2 |
| 6. 控制流与状态 | 分支完整吗？循环收敛吗？状态迁移和重复调用是否合法？ | 状态机、复杂分支、取消或回调 → R1／R4 |
| 7. 异常与故障 | 失败能否被准确感知？状态、资源和错误上下文是否保留？ | 错误返回、异常、超时、重试、降级 → R5 |
| 8. 内存与资源 | 所有权是否清楚？正常和失败路径都正确释放并限制资源吗？ | 分配、连接、锁、文件、线程、订阅、缓冲区 → R3 |
| 9. 并发与异步 | 共享数据、原子性、可见性、完成与取消竞争是否正确？ | 多线程、协程、异步任务、多实例共享状态 → R4 |
| 10. 数据一致性与幂等 | 事务与副作用边界在哪里？重复、乱序、部分失败能否恢复？ | 数据写入、消息、支付、分布式锁、补偿 → R6 |
| 11. 安全与隐私 | 身份、资源级授权、租户隔离、输入处理、凭据和日志是否安全？ | 新端点、文件／网络操作、秘密、权限或依赖变化 → R7 |
| 12. 性能与容量 | 在已确认规模下，时间、内存、I/O、队列、连接及任务是否可控？ | 热路径、查询、递归、批量、缓存、循环或并发变化 → R8 |
| 13. 接口与演进兼容 | 调用方、协议、配置、数据以及混合版本能否共存和恢复？ | 公共接口、存储格式、schema、默认值或发布变化 → R9 |
| 14. 测试与验证 | 断言能否区分正确与错误？目标缺陷和关键失败路径有回归证据吗？ | 每次检查相关已有测试；跨层契约按风险验证，见下节 |
| 15. 可读性与规范 | 命名、结构、注释和文档能否传达真实意图？是否满足适用规则？ | 先查项目规范；设计启发式见 design-smells |
| 16. 可观测性与上线安全 | 失败能否定位？发布、迁移、配置、开关和恢复是否有证据？ | 生产行为、运维路径或上线步骤变化 → R9／R10 |

R1–R11 的详细检查项在 [risk-checklists.md](risk-checklists.md)。涉及 SQL、Web UI、脚本／CI／基础设施或公共 API 时，同时读取 R11 中对应的领域补充，避免只套用服务端清单。

## 需求与规范取证

- 找到适用的 AGENTS.md／CLAUDE.md、CONTRIBUTING、CODING_STANDARDS、设计文档、接口约定和相关配置；尊重各自作用域与更高优先级约束。
- 仓库有明确取舍时，以其约定评价 Standards；若取舍产生可证实的可靠性或安全后果，在第三轴报告事实，不以“符合规范”掩盖实际缺陷。
- 需求语句 → 实现路径 → 验证证据建立对应关系。可将相同机制的多条要求合并，但不能遗漏验收行为。
- 区分功能要求、非功能要求和兼容承诺。必要的错误处理、权限校验和安全保护不因“规格未逐字要求”就自动成为 scope creep。
- 作者解释用于补足上下文；技术负责人声称已批准、发布紧急或测试“应该通过”，均不替代取证。
- 注释重点核对原因、不变量和调用契约；修改后过时的注释与文档需纠正，不能仅要求“多写注释”。
- 自动工具已执行并通过的机械规则无需逐项重报；结果过期、规则未启用或工具覆盖外的风险仍需审查。

## 测试审查

1. 从行为和风险选择证据，而不是从测试数量或覆盖率倒推正确性。
2. 检查断言真值：关键状态、输出、错误和副作用是否被断言？实现故意错掉时能否被测出？
3. 覆盖正常、边界、非法输入、异常，以及适用的重试、并发、取消、时间和版本迁移。
4. Mock／stub 应匹配真实接口语义；跨事务、进程、网络、序列化和数据库的行为，必要时检查真实链路。
5. 检查测试隔离、共享状态、时间与随机性、资源清理，以及失败是否被跳过、吞掉或重试掩盖。
6. 易复发缺陷建议保留能检出原错误的最轻回归。缺测试本身只有造成具体重要行为无有效保障时才形成有影响依据的 finding，不能按“没加测试”机械定级。
7. 真实环境、容量和长稳结果只能支持其负载、时长及故障模型；小型夹具不构成生产容量证明。
