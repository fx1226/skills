# 风险专项检查

由通用维度表触发，读取适用章节。每章是问题集，不是“发现即报”的规则：候选项须满足证据与影响门槛。以下要求按实际语言、协议和领域取舍；不凭空设置长度、精度、超时或容量上限。

## R1 初始化、生命周期与状态机

- 使用前是否建立有效状态？默认零值、空值和“尚未设置”是否被混淆？
- 必填字段、初始化顺序、依赖就绪和配置默认值是否正确？每个分支均成立吗？
- 对象是否在构造完成前注册回调、发布到共享位置或启动任务？
- 初始化中途失败时，已获得资源是否释放，半成品是否对外可见？
- start／stop／close／reset／重连的顺序、重复调用和失败后重入是否合法？
- 复用对象是否清掉旧请求、旧租户、缓存、回调和错误状态？
- 状态机是否覆盖合法事件及非法迁移？取消、超时、完成和销毁能否竞争？
- 循环是否有进展和可达退出条件？回调重入、递归和异常会不会破坏不变量？

## R2 输入、边界、数值与类型

- 从调用方与信任边界确认输入域：缺失、null、空串／集合、0、1、负数、重复、未知枚举。
- 检查阈值前／等于／后、最大合法值和一旦超限的处理；构造测试值本身也要符合语言安全语义。
- 索引、长度、分页、切片和区间的闭开端点一致吗？空集合、最后一页、终止符是否额外占空间？
- 单参数合法而组合非法：起止顺序、总和、乘积、长度与容量、偏移与剩余量。
- 加减乘、计数累加、长度乘元素大小、单位换算是否在**中间运算**就溢出？后赋给宽类型不自动修复。
- 缩窄、有符号／无符号转换、符号扩展、整数除法、除零、取模、位移按实际语言判断。
- 浮点的 NaN／Infinity、精度、比较、累计误差和舍入是否符合契约？金额和计量单位用领域要求判断。
- 跨语言／序列化边界的范围、精度、缺省值、未知字段与枚举处理一致吗？
- 时间戳单位、时区、夏令时、闰日、有效期边界和时钟回拨；测量耗时是否需单调时钟？
- 解码、规范化和校验顺序是否允许校验后出现另一种含义？
- 区分：整数溢出、缓冲区越界、精度损失、栈耗尽、容量耗尽，各有不同机制和证据。

## R3 内存与资源

- 明确分配、借用、转移、共享和释放责任；资源是否跨越其有效生命周期？
- 每个成功获取都检查正常、早返回、异常、取消和部分失败清理；顺序是否反向匹配依赖？
- 检查泄漏、双重释放、释放后使用、悬空引用、失效迭代器及缓冲区读写边界。
- 原始缓冲区的长度、容量、终止符和重叠复制是否正确？不把内存初始化等同于语义初始化。
- 文件、socket、数据库连接、锁、线程、定时器、监听器和订阅均有退出机制吗？
- 锁和连接是否被慢 I/O、回调、异常或不受控等待长期占用？
- 内存安全语言仍检查对象保留、无界集合、闭包引用及外部资源；不机械套用手动释放要求。
- 密钥／令牌等敏感资源的生命周期和清理按项目安全要求核对，避免在报告中复述秘密。

## R4 并发、异步与取消

- 确认真实并发模型：线程、协程、事件循环、多进程、多实例；哪些状态被共同访问？
- 检查原子性、可见性、内存顺序、不可变性，以及 check-then-act／读改写竞争。
- 锁覆盖的是完整不变量吗？锁顺序、嵌套、回调重入、跨 await 持锁可能死锁或饥饿吗？
- 条件等待、唤醒、通知和重检条件是否满足运行时契约？不能只看“有锁”。
- future／promise／任务的失败是否被接收？后台任务是否被追踪、等待或有明确生命周期？
- 取消请求不是已结束：取消之后回调、写入、资源访问和副作用如何收束？
- 完成与超时／取消竞争时，结果和清理是否只处理一次？
- 并发上限、背压、队列满载、批量扇出和关闭排空是否可靠？
- 竞争判断写出可行交错或同步关系；单次测试通过不是无竞争证明。

## R5 错误、超时、重试与降级

- 区分失败、空结果、未找到、无权限、取消和结果未知；不要用同一“成功默认值”掩盖。
- 错误是否在恰当层处理、保留因果和必要上下文，避免吞错或反复记录同一错误？
- 部分失败后内存、持久化和外部副作用是否一致？恢复动作会否再失败？
- 超时是否覆盖整个请求预算？逐层重试会否乘法放大流量或突破截止时间？
- 重试仅用于可重试条件；检查次数、退避、抖动、截止时间与取消。
- 超时后远端可能已成功；是否需查询、幂等标识或补偿？不能把超时当作确定失败。
- 降级／fallback 是否可接受、可辨识、可观测？过期数据是否可能违反安全或业务不变量？
- 日志的级别、频率和错误返回是否支持定位且不泄密；内部细节是否暴露给外部调用方？

## R6 一致性、事务、消息与幂等

- 写出需要保持的不变量和事务边界；本地事务是否真的包含所有相关写入？
- 并发更新、隔离级别、唯一约束、乐观锁与受影响行数是否共同保障不变量？
- 外部 API、数据库和消息不是天然一个原子事务；检查提交／发送之间的失败窗口。
- 重投、重复请求、乱序、迟到和消费者重启后，会否重复扣款、重复发送或状态回退？
- 幂等键的作用域、持久性、并发去重及过期策略与业务匹配吗？失败是否留下永久占位？
- 缓存写入／失效、主从延迟和读己之写的假设是否成立？
- 分布式锁的所有者、租约、续约、过期后旧持有者和 fencing 等机制按实际方案取证。
- 补偿、对账、重放和死信处理是否有可验证恢复路径？
- “恰好一次”“事务已保证”等结论必须落到具体系统和接口保证，不能靠名称推断。

## R7 安全与隐私

- 画清不可信输入和权限边界；认证、资源级授权、租户隔离及服务身份分别检查。
- 数据库、命令、模板、HTML、反序列化、文件路径和网络请求按实际 sink 检查注入风险。
- 路径穿越、符号链接、校验后使用竞争、压缩解包和文件权限会否逃逸目标范围？
- SSRF、重定向、DNS／地址变化、跨域和回调 URL 的校验是否覆盖真实访问路径？
- HTML／脚本上下文的输出编码、CSRF、会话与令牌生命周期按客户端与服务端契约判断。
- 秘密是否进源码、配置、日志、异常、URL、测试夹具或构建产物？报告用脱敏片段。
- 加密、随机数、签名验证和证书校验依赖项目安全规范与标准库；不自创协议。
- 新依赖、脚本和构建来源是否可信？漏洞结论核对实际版本、使用路径和适用条件。
- 输入规模、解压／解析膨胀、正则和密码学成本也属于拒绝服务面，联读 R8。
- 以最小、隔离、无破坏证据论证；不探测生产、不读取无关私密数据、不实施攻击性验证。

## R8 性能、容量与资源预算

- 用已确认的输入规模、调用频率及预算判断复杂度，不对非热路径凭直觉做优化要求。
- 检查嵌套循环、重复计算、全量扫描、拷贝、同步阻塞和频繁小 I/O。
- SQL 的 N+1、索引可用性、排序、分页、锁范围和返回规模是否有查询语义或计划支持？
- 缓存、队列、线程／任务、连接、重试和聚合结果是否有与业务匹配的上限、背压或淘汰？
- 解析器检查输入量、递归深度、节点数、输出膨胀和每单位输入的工作量，不能只限制原始长度。
- 超大批次、热点键、慢依赖、连接耗尽和重试风暴如何传播？
- 压测与长稳只在获授权环境按约定指标执行；局部基准不替代容量验收。
- 无数据支持的“这里可能慢”列为问题或建议，不制造确定的性能缺陷。

## R9 接口、数据与发布兼容

- 新旧客户端、服务、schema、配置和数据格式的兼容方向是否明确？
- 滚动发布／灰度下检查新读旧、新读新、旧读旧、旧读新及其实际可达组合。
- 字段新增／删除、类型与默认值、错误码、枚举、协议顺序、ABI／公共 API 的调用方是否适配？
- schema 迁移的锁、耗时、回填、失败恢复、幂等及前后版本共存是否可接受？
- 新版本写出的状态，旧版本回滚后还能读写吗？回退镜像不等于恢复数据。
- 是否需要先兼容读取、再启用写入／行为的分阶段方案？按系统契约判断，不强制某一种实现。
- 开关默认值、生效顺序、配置缺失、动态更新和禁用后的残留状态是否安全？
- 删除功能需检查旧调用方、定时任务、部署脚本、数据和运维手册，而不只是编译引用。

## R10 可观测性与运行恢复

- 关键失败、重试、拒绝、饱和、降级和数据异常能否被观察？是否有可关联请求／任务的上下文？
- 日志和指标是否准确表达成功／失败，避免虚假成功、告警风暴及高基数维度？
- trace／日志是否泄密、过量或在热路径造成显著负担？
- readiness、liveness、启动和优雅关闭是否与真实服务能力及资源排空一致？
- 变更是否引入新的配置、部署步骤、告警或恢复操作；对应文档与责任是否明确？
- 事故恢复所需的回放、补偿、开关、备份和回滚是否有适用证据？审查本身不执行生产操作。

## R11 领域补充

只读实际涉及的条目；已有专项技能或项目规范提供更精确规则时引用它，不在此复制全套标准。

### SQL／数据库
- 参数化、NULL 语义、排序稳定性、分页、唯一／外键约束、事务隔离与死锁。
- 读写规模、执行计划、锁表风险、迁移前后兼容及恢复；无授权不对共享数据库运行写入。

### Web／客户端 UI
- 加载、空、错误、禁用和重复提交状态；请求乱序、卸载后回调及前后端校验一致性。
- 键盘操作、语义、焦点、可访问名称、错误提示和适用的国际化／响应式要求。
- 浏览器安全与数据暴露联读 R7；只审变更涉及的体验，不扩大成全站重设计。

### Shell／CI／构建与基础设施
- 引号、参数边界、退出码、管道失败、路径／工作目录、环境差异及命令注入。
- 权限、秘密、依赖来源、可重现性、缓存隔离、破坏性命令、部署条件与回滚。
- 构建／测试脚本也可能下载、上传、重写快照、启动服务或连接生产，运行前核对传递行为。

### 公共库／SDK／底层接口
- 所有权、线程安全、生命周期、错误语义、版本与 ABI／API 兼容及调用者可见行为。
- 对应语言的专项规则（如 C 的未定义行为、对齐、别名和头文件契约）交由适用规范核实。
