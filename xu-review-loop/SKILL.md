# xu-review-loop

对同一个可复核的交付对象做「验证 → 独立审查 → 必要时修复与复验」。执行 Agent 负责验证和授权内的修复，审查 Agent 独立只读；主 Agent 定范围、派发、核对门禁和交付，不代做验证或审查。

## 1. 固定本轮契约

- **对象与目标**：确认工作目录、要交付或验证的对象、包含与排除的范围。用 `xu-code-review` 的「固定范围与证据」规则定位 Git、SVN、文件或补丁，不把空 diff 当成验证已有对象的障碍。约定执行和审查两侧如何独立生成同一格式的版本标识（如完整修订号或固定路径顺序的内容指纹）；涉及设备或远程环境时，再明确如何核实运行版本与送审对象对应。
- **验证计划**：逐项定唯一 ID、验证方式与通过条件。适用的构建和功能测试列为必验；也可用现有脚本、只读观察或其他足以支撑目标的证据。用户明确暂缓的项列在本轮范围外；未获授权或环境不具备的必验项记为受阻，不自动变成暂缓。
- **授权与上限**：明确能做的实现、修复与环境操作。检查脚本及其调用的副作用；已有脚本不代表获准重建、部署、中断流量或写外部状态。默认最多 10 次有效送审，可明确设为 1–20 次；同一失败连续修复 3 次仍不过则报告卡点。

先从用户要求、项目文档和已有脚本取证。仅在不同解释会改变对象、验收标准或授权时询问；其他不互相依赖且已授权的工作可以先做。

**完成条件**：记录对象／范围、必验计划、暂缓项、授权边界和送审上限；缺失的关键前提有明确卡点。

## 2. 选执行路径

- **程序门禁**：当前会话有兼容的 `workflow` 工具时，按 [调用契约](references/workflow.md) 执行。只有能运行本技能脚本并返回结构化子 Agent 结果的工具才算兼容。用户明确要求程序硬门禁而运行器不可用时，报告受阻，不降级。
- **子 Agent 编排**：无兼容运行器且未要求程序硬门禁时，使用实际可用的子 Agent 工具。派执行 Agent 和不同的、独立上下文的审查 Agent；各自复核现场，审查 Agent 不写工作区或环境。有工具权限约束时使用它，不把提示词约束称为硬隔离。异步派发凭完成通知推进，启动回执不算结果，不额外派占位 Agent。主 Agent 记录拟送审对象、已计轮次和结果，报告注明「子 Agent 编排，轮次和放行由主 Agent 核对」。
- **没有独立审查能力**：交付已取得的测试证据和缺口；没有通过结论，不由主 Agent 自审代替。

**完成条件**：选定路径与角色；若无法满足用户要求的门禁或独立性，明确报告卡点。

## 3. 验证、审查与返工

子 Agent 编排按以下顺序执行；程序门禁检查同一契约。

1. **验证**：已有对象直接验证；需要实现时先做授权内的必要改动。优先做可独立完成的验证，按授权修复并复验。每项必验结果记录通过／失败／受阻、对应版本、实际方法、环境、结果或卡点。必验项未通过或无法确认版本时不正式送审；仍可对独立部分做只读审查，单列证据和发现，不计正式送审，也不放行整轮。
2. **独立审查**：交接范围、版本指纹、改动或无改动说明和逐项证据。审查 Agent 按 `xu-code-review` 独立核对对象和相关上下文，返回实际审查的版本、是否验证充分、具体证据缺口、阻塞项和非阻塞项。只证明链路某一层的证据不外推到其他层；需要复跑有副作用的动作时报告缺口。
3. **判定和计轮**：仅当审查返回**同一对象的有效结论**才计一轮。**全部必验项有对应该对象的通过证据、独立审查确认充分、且无未解决的阻塞项**，三者同时满足才通过。自测失败不计轮；执行或审查调用失败、证据对象漂移不计轮，报告断点和已用轮次，不无限重试或重开绕过上限。
4. **返工**：只把具体阻塞项和缺哪个验收项、要补什么证据交回执行 Agent；仅缺证据时不强制改代码。改动后按影响复验，与新对象不再对应的证据不得挪用，并重新独立审查。到上限仍不过则停止。

**完成条件**：通过、受阻、流程故障或超限停止均有对应证据；范围、对象、轮次和残留问题对得上。

## 4. 交付

报告路径（程序门禁／子 Agent 编排）、已用轮次、实际验证和审查的对象、逐项证据、阻塞或非阻塞事项、暂缓项。交付前复核涉及的版本／指纹；如有漂移，只能说明旧结论适用的对象，不给新版本放行。没有真实链路证据时写明验证到了哪一层。

通过只覆盖本轮范围，不授予提交或部署权限。有单独授权才执行对应动作并报告范围；受阻和停止时说明下一步需要什么。
