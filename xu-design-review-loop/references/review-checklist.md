# 设计评审清单

对固定版本按四个视角只读取证，按适用性检查并说明覆盖范围；无法核实的事项列具体缺口。

1. **需求／项目**：需求及版本是否可追溯，每项验收条件是否有承接；约定、范围和假设是否有依据；关键问题是否已确认。
2. **软件研发**：现状调用链和方案取舍是否有证据；模块职责、接口、数据和状态是否足以实现；异常、失败、边界、兼容和迁移是否闭合。
3. **测试**：验收、边界、异常和回归是否有可执行的验证方式；依赖、环境及不可验证部分是否明确。
4. **受影响模块**：检查调用方、共享接口、数据及状态的影响；涉及 CLI、前端、API 或设备时核对其适用契约和跨模块影响。

报告所审版本、证据与覆盖范围；区分阻塞项、证据／决策缺口、非阻塞建议、范围外观察。问题定位到需求或设计位置，并给出触发条件及影响，或明确缺失的证据／决策；只凭偏好不列缺陷。无阻塞和必需证据缺口才可给出当前版本的独立评审通过结论。
